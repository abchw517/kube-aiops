# kube-aiops「资源管理」首版 PRD

**版本** v1.2<br>
**更新日期** 2026-11-18<br>
**目标用户** 公司内部 OPS

## 1. 目标与交付范围

将本地及外部 Kubernetes 集群纳入统一管理。OPS 可以用真实采集数据确认接入结果，按环境和业务线查看历史诊断，并在原连接上处理首采前环境修正和凭据轮换。

首版交付本地自动采集、外部 API Server 直连接入、首采验证、环境与业务线维护、命名空间分配、分级授权、首采前环境修正、凭据轮换、连接删除及本地重新连接。隔离网络下的远端主动上报、待接入连接的定时重试、许可证和计费列入后续范围。

## 2. 页面与数据展示

「资源管理」是一级模块，与「诊断控制台」「系统管理」并列。「运维知识库」位于「诊断控制台」下方。首版采用以下页面结构，默认打开「Kubernetes 集群管理」列表。

| 页面或入口 | 内容与操作 |
|---|---|
| 资源管理 → Kubernetes 集群管理 | 集群列表、接入状态、配置连接、重新校验、轮换凭据、首采前修正环境、命名空间分配及删除连接。采集状态区直接展示已收到的首批节点、命名空间和诊断数据，标出 `NotReady` 节点。 |
| 资源管理 → 环境管理 | 列表展示环境名称、环境 ID 和行级操作，列表下方新增环境。 |
| 资源管理 → 业务线管理 | 列表展示业务线名称、业务线 ID 和行级操作，列表下方新增业务线。 |
| 诊断控制台 → 环境 → 集群或命名空间 | 详情仅展示历史诊断。集群详情展示集群级诊断和已分配命名空间的诊断。进入某个命名空间时，仅展示该命名空间的诊断。 |
| 诊断控制台 → 业务线 → 集群或命名空间 | 详情仅展示当前业务线所关联命名空间的历史诊断。进入某个命名空间时，展示该命名空间的完整历史诊断。 |

节点故障等集群级诊断统一在环境入口展示。节点列表位于「Kubernetes 集群管理」采集状态区。集群与命名空间的诊断详情页均无需工作负载列表。

### 2.1 环境管理与业务线管理页面调整

两个子页位于「资源管理」，使用相同的列表及编辑交互。首版操作权限按《系统管理首版 PRD》的最新约定执行，由系统管理员维护。旧权限设计中关于委派操作的描述，以该约定为准。

| 项目 | 环境管理 | 业务线管理 |
|---|---|---|
| 列表字段 | 环境名称、环境 ID、操作 | 业务线名称、业务线 ID、操作 |
| 行级操作 | 编辑、删除 | 编辑、删除 |
| 页底入口 | 新增环境 | 新增业务线 |

- **列表。** 每条记录占一行，名称和 ID 左对齐，操作在右侧。已存在的记录默认只读展示。环境预置项按「研发、测试、预发布、生产」排列，新增项追加在列表后。
- **新增。** 点击列表底部按钮打开表单，填写名称和 ID。ID 由管理员填写，在各自目录内唯一。新 ID 以小写字母开头，可使用小写字母、数字和连字符，最多 128 字节。未修改的存量 ID 沿用原值。必填、重复 ID 和无效格式在表单内提示。
- **编辑。** 点击行内「编辑」打开弹窗，名称和 ID 均可编辑。保存后列表展示新 ID。关联集群、命名空间和已有角色授权继续引用同一目录条目，删除保护随新 ID 生效。历史 ID 在条目仍存在时归该条目，可改回旧 ID，其他条目不能占用。提供「取消」「保存」及「删除」。重复 ID 或格式错误均在表单内提示，保存失败保留当前输入。
- **删除。** 行内和编辑弹窗中的「删除」进入同一个确认流程。按 §6.3 检查引用。有引用时禁止删除并列出关联的集群或命名空间。无引用时确认后删除并刷新列表。
- **空态。** 列表为空时显示「暂无环境」或「暂无业务线」，底部仍提供新增入口。


## 3. 环境、业务线和命名空间

- 首版预置「研发、测试、预发布、生产」。系统管理员可新增、改名及修改 ID。
- 同一 Kubernetes 集群只归属一个环境，可关联多条业务线。为同一集群追加业务线时复用已有连接。
- 业务线跨环境共用，由系统管理员维护。
- 具备对应集群操作权限的 OPS 在「Kubernetes 集群管理 → 命名空间归属」先选业务线，再勾选要关联的已采集命名空间。已关联项自动勾选，取消勾选可解除该业务线的关联。独立业务集群直接显示其唯一业务线。命名空间列表可独立纵向滚动，业务线选择和保存按钮保持可见。
- 一次保存只提交当前集群、当前业务线的新增与移除项，保留同一命名空间关联的其他业务线和当前列表外的归属。每个命名空间至少关联一条业务线时为已分配。未分配项从常规诊断详情隐藏，可在命名空间归属弹窗查看和处理。
- 业务线按命名空间当前归属展示历史诊断。新增关联后，新关联的业务线能查看该命名空间的全部历史。移除关联后，原业务线入口随即停止展示该命名空间及其历史诊断，仍有关联的业务线继续可见。
- 例如「研发 → dev-k8s → dev-base」同时关联有数、云帆、架构、运维、享钱和数字化时，六条业务线均可查看 `dev-base` 的同一份完整诊断历史。

## 4. 权限

| 角色或授权 | 首版可执行操作 |
|---|---|
| 系统管理员 | 指定、撤销环境管理员，查看和补齐未归属的本地集群，删除及重新连接本地集群。 |
| 环境管理权限 | 新增、改名环境，指定环境管理员。撤销由系统管理员执行。 |
| 环境管理员 | 在负责的环境内为用户授予环境权限，查看该环境的集群状态和运行详情。修改连接、重新校验等操作需相应集群授权。 |
| 环境查看权限 | 查看环境中的集群、采集状态和对应入口允许的诊断数据。 |
| 环境「新增集群」权限 | 在对应环境创建连接。保存成功后，创建者自动获得该集群的管理权限，可删除连接及向合资格用户授权。 |
| 集群操作授权 | 按具体授权管理对应集群，包括修改连接、重新校验、分配命名空间、轮换凭据等。 |
| 业务线管理权限 | 维护跨环境共用的业务线。 |

- 授予集群权限前，接收人须具备该集群当前所在环境的权限。撤销环境权限时，该环境下的集群授权随之失效。用户重新获得环境权限后，须重新授予集群权限。
- 业务线入口也按集群当前环境校验访问权限。用详情直链访问时执行相同校验。
- 集群环境修正由系统管理员在首次采集成功前执行。

## 5. 接入与采集

### 5.1 本地集群

首次部署时自动识别 kube-aiops 所在的 Kubernetes 集群并开始采集。归属补齐前由系统管理员查看。系统管理员填写环境、业务线及集群名称后，按归属及授权显示。

本地节点采集使用当前 API Deployment 的 ServiceAccount。Kubernetes 返回节点列表权限不足时，采集详情提示检查实际运行账号的 `list nodes` 权限。平台管理员恢复该权限后，系统管理员可点击「重新校验」，成功获取节点状态后清除该提示。

### 5.2 外部集群

1. OPS 选择已有环境、至少一条业务线，填写集群名称。三项均为保存必填项。
2. 提交一种连接配置。支持带内嵌 CA 和静态凭据的 kubeconfig、API Server 地址加 ServiceAccount Token、API Server 地址加客户端证书及私钥。
3. 点击「测试连接」后，系统用当前表单提供的新凭据发起 HTTPS 请求并检查节点读取权限。新凭据仅在本次请求的内存中使用，测试不写入 SQLite。测试成功后页面提示连接结果，创建或更新集群仍由「保存」触发。API Server 无法访问时提示「连接失败，网络不可达」。凭据有效但不能读取节点时提示「节点读取权限不足」。
4. 外部直连的接入配置和凭据密文保存在 SQLite 中。首次保存时服务自动在 SQLite 持久化目录生成密钥。旧挂载记录保留在集群列表，补录并验证凭据后恢复接入。校验失败的新增配置仍可保存为「待接入」，OPS 修复后可手动「重新校验」。
5. 校验通过后开始 5 分钟首采窗口。收到节点及其状态，或至少一条真实 K8sGPT 诊断，即标记为「已接入」。已收到的数据可在「Kubernetes 集群管理」内直接查看。

### 5.3 状态

| 条件 | 页面显示 |
|---|---|
| 校验通过后未满 5 分钟，且无有效节点数据或诊断 | 等待首次采集。 |
| 校验通过满 5 分钟，且节点和诊断均未收到 | 首次采集超时，提示检查采集连接和目标集群的 K8sGPT 配置。 |
| 先收到有效诊断，满 5 分钟仍无节点数据 | 保持「已接入」，提示「集群状态信息采集异常」。 |
| 已接入的外部直连集群手动「重新校验」时，节点列表读取失败 | 立即显示「已接入 · 节点校验失败」。详情显示脱敏原因，并展示上一次成功的历史节点快照及时间。周期采集达到过期阈值后，列表优先显示「节点数据已过期」。 |
| 节点检查成功，任一节点为 `NotReady` | 集群异常，采集状态区单独标出异常节点。 |
| 节点全部 `Ready`，首采窗口结束时无诊断 | 当前集群正常。 |
| 节点全部 `Ready`，已确认 K8sGPT 未安装或诊断读取权限不足 | 当前集群正常，同时显示诊断采集问题及原因。 |
| 节点全部 `Ready`，K8sGPT 发现 Pod 或 PVC 故障 | 当前集群正常，同时提示「发现工作负载故障」。 |
| 首采超时后首次收到有效节点数据 | 更新为「已接入」，清除首采超时或节点采集异常提示，按最新节点状态显示。 |

节点统一每 **5 分钟**采集一次。「重新校验」立即检查当前连接。5 分钟内重复手动校验失败时，更新最近检查结果，按原周期累计失败次数。已接入集群连续两轮周期采集未成功时，保留最后一次成功采集的数据和时间，并显示「节点数据已过期」。后续成功读取节点时更新快照，清除读取错误和过期提示，按最新节点状态显示。

## 6. 维护与删除

### 6.1 首采前环境修正

系统管理员在首次收到有效节点状态或真实 K8sGPT 诊断前可以修正集群环境。首采成功后锁定环境。目录条目的 ID 或名称更新属于目录维护，已关联的集群继续归属同一环境。

### 6.2 凭据轮换

有集群管理权限的 OPS 在原连接提交新凭据。新凭据校验通过后切换，校验失败时保留原凭据并显示原因。原凭据也失效时，显示「凭据失效」，节点数据按连续两轮失败的规则标记过期。

### 6.3 删除与重新连接

| 对象 | 规则 |
|---|---|
| 环境 | 采用引用保护。存在归属集群时阻止删除，并列出涉及的集群。解除关联或删除相应连接后可再删除环境。 |
| 业务线 | 采用引用保护。仍关联集群或命名空间时阻止删除，并列出相关引用。解除关联后可再删除业务线。 |
| 集群连接 | 停止采集，清理 kube-aiops 内该连接的历史节点、资源和诊断数据。已发布的运维知识库文档独立保留。 |
| 本地集群连接 | 系统管理员可删除。删除后保留「已删除」记录和「重新连接」按钮。系统重启后保持「已删除」。管理员点击「重新连接」后，沿用删除前的环境、业务线和集群名称，直接开始新一轮采集。 |

## 7. 试点验收

使用 **研发、测试两个环境及两个 Kubernetes 集群**。研发环境放置一个本地集群，测试环境放置一个外部集群。外部集群依次验证三种接入方式，再从测试迁至研发。

| 验收场景 | 通过标准 |
|---|---|
| 本地自动采集 | 首次部署后自动采集。补齐归属前仅系统管理员可查看。补齐后可在集群接入页验证节点、命名空间和诊断数据。节点请求返回 403 时，采集详情提示核对实际 API ServiceAccount 的 `list nodes` 权限。恢复权限后手动重新校验，状态更新并清除错误提示。 |
| 三种外部接入方式 | 分别用 kubeconfig、Token、客户端证书及私钥完成真实接入验证，同一集群只保留一条连接。 |
| 测试连接与加密保存 | 在未预配密钥的环境使用 kubeconfig 测试成功，列表保持原样。点击「保存」后记录进入 SQLite，服务重启后使用已保存凭据恢复连接。 |
| 接入失败 | 分别验证网络不可达、节点读取无权，能看到具体原因，保存待接入并手动重新校验。 |
| 外部集群已退役或无法访问 | 外部 API 停止响应后，在上次成功采集 5 分钟内点击「重新校验」，列表显示节点校验失败，详情保留上次成功的历史快照与时间。恢复访问并再次校验成功后，刷新节点状态并清除错误。 |
| 首采及状态 | 验证无数据超时、仅诊断先到、节点迟到恢复、`NotReady`、诊断采集异常、工作负载故障提示。 |
| 节点数据过期 | 首次采集失败后未标记过期，连续第二次失败后标记，继续显示最后成功数据和时间，成功后自动清除。 |
| 环境与业务线目录 | 两个页面均按行显示名称、可编辑 ID 和操作。新增入口位于列表底部。重复或无效 ID 被拒绝，更新 ID 后关联保持，删除仍检查引用。 |
| 页面与命名空间 | 先选择业务线，再从可滚动列表批量勾选该集群已采集的命名空间并保存。重新打开时回填关联。一个命名空间关联两条业务线时，两边看到相同的完整历史。解除其中一条时保留其余关联。独立业务集群仅可分配给所属业务线。未分配项仅在授权分配入口可见。 |
| 分级授权 | 验证环境查看与集群操作的权限边界、创建者自动获权、环境撤权后集群授权失效、恢复环境权限后需重新授予集群权限。验证环境管理者可指定环境管理员，撤销由系统管理员执行。 |
| 首采前环境修正 | 系统管理员可以修正首次选错的环境。首次采集成功后拒绝调整集群环境，目录 ID 编辑不改变集群归属。 |
| 凭据轮换 | 校验成功后切换，校验失败时原凭据继续生效，原凭据已失效时能看到对应提示。 |
| 删除及本地恢复 | 有引用的环境或业务线无法删除。删除集群连接后停止采集并清理历史，知识库文档仍可查看。本地连接删除后跨重启保持状态，点击「重新连接」沿用三项原配置，重新采集，已清理历史保持清理状态。 |

## 8. 评审项

1. 页面结构和默认入口采用「集群接入、环境管理、业务线管理」三页方案，默认进入集群列表。待分配命名空间放在集群接入的分配区。
2. 删除环境或业务线采用引用保护。待明确本地集群「已删除」记录的原归属是否继续占用引用，以及原环境或业务线已被删除时，「重新连接」如何处理。
3. 同一连接的节点与诊断分别验收。诊断在首采超时后先到、节点仍无数据时的具体恢复文案待补齐。
