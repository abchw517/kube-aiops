## 1. 目标与现状

值班人员应能用原始报错或中文症状找到适用手册，判断执行下一项检查的条件，确认恢复后把结果关联回已有知识。故障案例记录一次处理过程，排障手册维护可复用方法。两者独立版本化。

当前可复用列表、文档修订、导入、远端同步、AI 问答和 #101 的复核结论。当前实现的三个限制是列表缺少正文搜索、Finding 回写采用临时环境与业务标签、发布入口可以直接写入可检索文档。现有平台访客和 LDAP 角色的授权白名单仅支持诊断相关能力，内置系统管理员可使用 Wiki。首版以现有授权为准，试点由当前获授权人员执行。面向 LDAP 值班人员扩展 Wiki 权限需独立评审。 [现有知识库代码](https://github.com/abchw517/kube-aiops/tree/ca40d7f/api/internal/wiki) · [现有平台授权](https://github.com/abchw517/kube-aiops/blob/ca40d7f/api/internal/permissions/platform_authorization.go)

## 2. 交付范围

| 优先级 | 交付内容 |
| --- | --- |
| P0 值班闭环 | 关键词搜索和筛选、带版本的结构化详情、Finding 推荐和关联、从已保存结论创建案例草稿、手工建稿与修订、提交审核和撤回、权限一致性、数据迁移。 |
| P0 现有链路适配 | 保留现有 AI 问答及远端同步入口。接入统一范围与发布状态检查，导入及同步写入候选版本，现有 Finding 发布入口改为创建候选草稿。 |
| P1 交付 | 章节级 AI 引用与深链、知识反馈与复核提醒、同步任务记录与逐项重试。 |
| 后续评估 | LDAP 专用 Wiki 权限、向量检索、复杂审批链、多源合并、自动执行。 |

商业范围为现有内部运维使用场景。知识引用经过授权的诊断、案例和手册，不自动触发集群操作。首次发布前用试点授权范围内的故障样本和手册验证完整流程。

## 4. 核心业务规则

### 4.1 内容、版本与范围

| 知识类型 | 可提交审核的最小信息 |
| --- | --- |
| 排障手册 | 症状、适用与排除条件、匹配信号、按序检查及预期、恢复验证、升级路径。 |
| 故障复盘 | 现象、发生时间或时间范围、受影响对象、证据来源、已验证或待确认的结论、处置与恢复验证。关联 Finding 时固定来源版本。未知项可明确标记待确认。 |
| 操作规程 | 前置条件、影响范围、按序步骤、停止条件、回滚、验收。 |
| 常见问题 | 问题、答案、适用条件和来源。 |

- 每条知识保留稳定 ID。每次发布产生只读快照。编辑新稿期间，原生效版本可以继续阅读。审核人按送审时的版本及范围发布，旧版本提交返回冲突。
- **可见范围**是可访问的授权目标，P0 使用明确的集群实例和命名空间组合；**适用范围**决定诊断推荐，可附环境、业务、资源类型、信号或组件限制。普通搜索中可见但不适用的条目可保留并提示；诊断推荐仅使用同时满足两种范围和匹配规则的条目。
- 从 Finding 生成的案例固定在原始范围，提交时由服务端解析。跨范围经验沉淀为独立的脱敏手册。命名空间多业务归属时保留真实业务 ID 集合。研发和测试环境可按既有规则不填写业务线。目录无法解析、需要业务归属的范围缺失归属或无命名空间时标记「范围待确认」，可保存草稿。修复目录归属后重新解析；无命名空间的原始案例在 P0 保留治理状态。禁止用集群名称填充业务或自动打通共享范围。
- P0 只对排障手册支持多个明确批准的可见目标。目标集合由服务端逐项校验，扩大范围时重审。内部案例、原始诊断和手册各自校验读权限，链接和计数也受约束。
- 本地原始诊断、已保存复核、知识文档和关联均独立。关联键使用实例标识和现有稳定 Finding 身份，固定关联时所见的手册版本。唯一约束保证重复提交只返回一条关系。手册关联不生成版本，内容修订走草稿流程。

### 4.2 权限矩阵

| 操作 | 当前 Wiki 读者 | 当前 Wiki 发布人员 | 系统管理员 |
| --- | --- | --- | --- |
| 搜索、详情、推荐、问答 | 需条目范围的读取权限 | 同读者规则 | 按现有管理权限 |
| 从 Finding 建稿、建立关联 | 无 | 需 Finding 读权限及目标 Wiki 发布权限 | 按现有管理权限 |
| 编辑、送审、审核、撤回 | 无 | 需相应范围的发布权限，涉及多目标时逐项校验 | 按现有管理权限，同时执行双人审批规则 |
| 注册或停用来源 | 无 | 无，现有同步权限仅用于获准来源的操作 | 按现有来源管理权限 |

搜索时按条目可见目标逐项判断。普通读者读取共享知识只要求至少一个批准目标且自己有该目标的权限；诊断上下文推荐还须当前 Finding 的目标也在可见及适用范围内。候选编辑、发布和撤回按变更涉及的目标全集校验。

### 4.3 审核、撤回与失效

- 草稿可保存、送审、驳回后修改或放弃。编辑只在草稿上生效。审核与发布由已有 Wiki 发布权限约束。涉及生产目标的内容发布或扩大可见范围时须由另一位拥有目标权限的管理员审核。常规现有范围允许同一发布人经预览确认。试点前验证生产场景有两位合格审核人。
- 审核预览显示最终脱敏正文、差异、来源、适用条件和可见范围。必填信息和目标校验通过后可发布。相同幂等键加相同请求返回同一结果；同键不同请求、基线过期或状态已变更返回冲突。成功事件写入操作审计，包含条目、版本、操作者、变更动作和目标范围。
- 已发布知识可撤回。撤回后普通列表、详情、诊断推荐和 AI 上下文停止使用该版本，历史通过治理入口按权限查看。已被新版本替代但未撤回的历史版本可按权限打开，并提示查看当前版本。
- 新条目提交审核时设置下次复核日期。一般手册与 FAQ 建议 180 天，生产操作规程建议 90 天，责任人可提前复核。到期手册标明待复核并降序，过期生产操作规程退出推荐和 AI；人工浏览显示过期状态。移交责任团队由有权管理员操作并留痕。

发布状态与复核状态分开。草稿按候选管理，复核到期按条目和生效版管理。

| 动作 | 原状态 | 结果 |
| --- | --- | --- |
| 保存编辑 | 新建、草稿、已驳回 | 创建或更新候选草稿，既有生效版不变。 |
| 送审 | 草稿 | 固定候选内容、目标和基线，进入待审核。 |
| 驳回 | 待审核 | 保存原因，回到可编辑状态。 |
| 发布 | 待审核 | 创建新只读版本并切换当前生效版；原版保留历史。 |
| 撤回 | 已发布 | 条目整体退出普通阅读和推荐，保留历史；重新生效须走新候选审核。 |
| 放弃 | 草稿、已驳回 | 停止候选流程，既有生效版不变。 |

### 4.4 搜索和 AI

- 查询支持报错全文、精确 Reason、资源类型和中文词。结果先按权限、状态过滤，再排序与分页。筛选值和总数从同一有权集合产生。使用稳定 ID 打破同分排序，分页切换或改变筛选后结果可重现。
- 诊断推荐先匹配明确的信号或资源加症状，再按已验证程度和复核时间排序。返回最多 3 条并显示命中原因。范围不适用、候选不足、服务异常分别反馈；失败时原详情和现场证据仍可用。
- 现有 AI 问答及诊断复核都只检索当前有权、可推荐的版本。区分手册建议、历史案例和现场证据；没有匹配时显示无答案。P1 验证每处引用对应本次检索提供的条目、版本与章节，输出回传前重查发布状态和授权。章节链接固定到引用版本。读者可提交「有帮助」或「需复核」，按条目、版本和章节保存。现行版的待处理反馈进入知识治理，完成复核后标记已处理。复核日前 14 天显示页面提醒。AI 输出需人工确认后才能成为发布正文。

### 4.5 导入、迁移及回退

- 手工、导入、同步和诊断入口共用候选版本机制。同步按来源 ID 和远端页 ID 去重，正文哈希相同不新建版本。远端失败保留上次生效版本；完整枚举才标记疑似缺失，治理人员可撤回。来源停用或明确撤权后立即阻断关联内容的对外分发。P1 持久化手动、定时和重试记录，显示最近整源成功时间与逐页结果。可对失败或中断的任务整源重试，或仅重试失败页。单页重试不会把其他页标成缺失。
- 增量迁移 SQLite，保留知识 ID、版本、可追溯的远端来源和原范围锚点。现有可解析、有效且未标记缺失条目保持原有读取范围，标记「历史待复核」；无验证记录的存量不进入诊断及 AI 推荐。无法解析的条目进入治理待归类，既有历史保留。
- 上线先备份 SQLite 并核对迁移报告，再切换全部读写入口。迁移可重跑。切换后如需回退，优先恢复旧界面并保持新可见性约束；若需恢复旧数据库，从备份和审计记录核对切换后的写入，有序回放已确认数据。旧读链接继续受版本和权限规则约束。旧的直接发布请求返回冲突并提示改用草稿入口。现有批量导入及同步更新为只创建候选。

## 5. 发布验收

| 场景 | 通过条件 |
| --- | --- |
| 真故障检索 | 三类试点各准备至少 5 种经值班人员标注的查询，覆盖精确报错和中文变体。前三命中率至少 80%，关闭模型后仍能找出相同规则命中的手册。 |
| 值班任务 | 至少两位试点值班人员分别使用 Finding 推荐和直接搜索，能从详情读出第一项有效的验证动作、适用条件与预期结果。记录寻找首项步骤的用时基线。 |
| 发布与撤回 | 保存复核、建立关联、草稿和来源同步均不直接产生生效的新知识。仅审核发布后生效。撤回后列表、详情、推荐和 AI 在下一次请求均不返回该内容。 |
| 权限 | 正负授权夹具覆盖访问、筛选项、总数、关联计数、引用和 AI 上下文；同 ID 跨实例时各自独立。访客和 LDAP 默认角色维持当前可见范围。 |
| 迁移与性能 | 用脱敏旧库验证重跑不重复，旧 ID 和已授权历史版本可定位。1 万条知识固定数据集运行不少于 100 次暖态搜索，服务端 p95 ≤ 500 ms 为试点目标，记录环境及结果。 |

试点后观测搜索无结果率、故障关联手册比例、撤回传播验证和逾期复核数量。统计只采集必要字段，保留权限约束。

## 6. 评审与开工

生产试点使用真实资源目录、两位生产审核人、共享手册目标名单、脱敏存量数据和公司 Wiki 来源进行验收。页面、功能、故事、任务和测试的追踪关系见 [开发任务](04-development-tasks.md)。
