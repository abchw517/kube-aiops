### 1. 目标与现状

值班人员应能用原始报错或中文症状找到适用手册，判断执行下一项检查的条件，确认恢复后把结果关联回已有知识。故障案例记录一次处理过程，排障手册维护可复用方法。两者独立版本化。

P0 立项时可复用列表、文档修订、导入、远端同步、AI 问答和 #101 的复核结论。立项时的三个限制是列表缺少正文搜索、Finding 回写采用临时环境与业务标签、发布入口可以直接写入可检索文档。当时的平台访客和 LDAP 角色授权白名单仅支持诊断相关能力，内置系统管理员可使用 Wiki。首版以现有授权为准，试点由当前获授权人员执行。面向 LDAP 值班人员扩展 Wiki 权限需独立评审。 [现有知识库代码](https://github.com/abchw517/kube-aiops/tree/ca40d7f/api/internal/wiki) · [现有平台授权](https://github.com/abchw517/kube-aiops/blob/ca40d7f/api/internal/permissions/platform_authorization.go)

### 4. 核心业务规则

#### 4.1 内容、版本与范围

| 知识类型 | 可提交审核的最小信息 |
| --- | --- |
| 排障手册 | 症状、适用与排除条件、匹配信号、按序检查及预期、恢复验证、升级路径。 |
| 故障复盘 | 现象、发生时间或时间范围、受影响对象、证据来源、已验证或待确认的结论、处置与恢复验证。关联 Finding 时固定来源版本。未知项可明确标记待确认。 |
| 操作规程 | 前置条件、影响范围、按序步骤、停止条件、回滚、验收。 |
| 常见问题 | 问题、答案、适用条件和来源。 |

- 每条知识保留稳定 ID。每次发布产生只读快照。编辑新稿期间，原生效版本可以继续阅读。审核人按送审时的版本及范围发布，旧版本提交返回冲突。
- **可见范围**是可访问的授权目标，P0 使用明确的集群实例和命名空间组合；**适用范围**决定诊断推荐，可附环境、业务、资源类型、信号或组件限制。普通搜索中可见但不适用的条目可保留并提示；诊断推荐仅使用同时满足两种范围和匹配规则的条目。
- 从 Finding 生成的案例固定在原始范围，提交时由服务端解析。跨范围经验沉淀为独立的脱敏手册。命名空间多业务归属时保留真实业务 ID 集合。研发和测试环境可按既有规则不填写业务线。目录无法解析、需要业务归属的范围缺失归属或无命名空间时标记「范围待确认」，可保存草稿。修复目录归属后重新解析；无命名空间的原始案例在 P0 保留治理状态。禁止用集群名称填充业务或自动打通共享范围。
- P0 只对排障手册支持多个明确批准的可见目标。目标集合由服务端逐项校验，扩大范围时重审。内部案例、原始诊断和手册各自校验读权限，链接和计数也受约束。
- 本地原始诊断、已保存复核、知识文档和关联均独立。关联键使用实例标识和现有稳定 Finding 身份，固定关联时所见的手册版本。唯一约束保证重复提交只返回一条关系。手册关联不生成版本，内容修订走草稿流程。

#### 4.2 权限矩阵

| 操作 | 当前 Wiki 读者 | 当前 Wiki 发布人员 | 系统管理员 |
| --- | --- | --- | --- |
| 搜索、详情、推荐、问答 | 需条目范围的读取权限 | 同读者规则 | 按现有管理权限 |
| 从 Finding 建稿、建立关联 | 无 | 需 Finding 读权限及目标 Wiki 发布权限 | 按现有管理权限 |
| 编辑、送审、审核、撤回 | 无 | 需相应范围的发布权限，涉及多目标时逐项校验 | 按现有管理权限，同时执行双人审批规则 |
| 注册或停用来源 | 无 | 无，现有同步权限仅用于获准来源的操作 | 按现有来源管理权限 |

搜索时按条目可见目标逐项判断。普通读者读取共享知识只要求至少一个批准目标且自己有该目标的权限；诊断上下文推荐还须当前 Finding 的目标也在可见及适用范围内。候选编辑、发布和撤回按变更涉及的目标全集校验。

#### 4.3 审核、撤回与失效

- 草稿可保存、送审、驳回后修改或放弃。编辑只在草稿上生效。审核与发布由已有 Wiki 发布权限约束。涉及生产目标的内容发布或扩大可见范围时须由另一位拥有目标权限的管理员审核。常规现有范围允许同一发布人经预览确认。试点前验证生产场景有两位合格审核人。
- 审核预览显示最终脱敏正文、差异、来源、适用条件和可见范围。必填信息和目标校验通过后可发布。相同幂等键加相同请求返回同一结果；同键不同请求、基线过期或状态已变更返回冲突。成功事件写入操作审计，包含条目、版本、操作者、变更动作和目标范围。
- 已发布知识可撤回。撤回后普通列表、详情、诊断推荐和 AI 上下文停止使用该版本，历史通过治理入口按权限查看。已被新版本替代但未撤回的历史版本可按权限打开，并提示查看当前版本。
- 新条目提交审核时设置下次复核日期。一般手册与 FAQ 建议 180 天，生产操作规程建议 90 天，责任人可提前复核。到期手册标明待复核并降序，过期生产操作规程退出推荐和 AI；人工浏览显示过期状态。移交责任团队由有权管理员操作并留痕。

发布状态与复核状态分开。草稿按候选管理，复核到期按条目和生效版管理。

| 动作 | 原状态 | 结果 |
| --- | --- | --- |
| 保存编辑 | 新建、草稿、已驳回 | 创建或更新候选草稿，既有生效版不变。 |
| 送审 | 草稿 | 固定候选内容、目标和基线，进入待审核。 |
| 驳回 | 待审核 | 保存原因，回到可编辑状态。 |
| 发布 | 待审核 | 创建新只读版本并切换当前生效版；原版保留历史。 |
| 撤回 | 已发布 | 条目整体退出普通阅读和推荐，保留历史；重新生效须走新候选审核。 |
| 放弃 | 草稿、已驳回 | 停止候选流程，既有生效版不变。 |

#### 4.4 搜索和 AI

- 查询支持报错全文、精确 Reason、资源类型和中文词。结果先按权限、状态过滤，再排序与分页。筛选值和总数从同一有权集合产生。使用稳定 ID 打破同分排序，分页切换或改变筛选后结果可重现。
- 诊断推荐先匹配明确的信号或资源加症状，再按已验证程度和复核时间排序。返回最多 3 条并显示命中原因。范围不适用、候选不足、服务异常分别反馈；失败时原详情和现场证据仍可用。
- 现有 AI 问答及诊断复核都只检索当前有权、可推荐的版本。区分手册建议、历史案例和现场证据；没有匹配时显示无答案。P1 验证每处引用对应本次检索提供的条目、版本与章节，输出回传前重查发布状态和授权。章节链接固定到引用版本。读者可提交「有帮助」或「需复核」，按条目、版本和章节保存。现行版的待处理反馈进入知识治理，完成复核后标记已处理。复核日前 14 天显示页面提醒。AI 输出需人工确认后才能成为发布正文。

#### 4.5 导入、迁移及回退

- 手工、导入、同步和诊断入口共用候选版本机制。同步按来源 ID 和远端页 ID 去重，正文哈希相同不新建版本。远端失败保留上次生效版本；完整枚举才标记疑似缺失，治理人员可撤回。来源停用或明确撤权后立即阻断关联内容的对外分发。P1 持久化手动、定时和重试记录，显示最近整源成功时间与逐页结果。可对失败或中断的任务整源重试，或仅重试失败页。单页重试不会把其他页标成缺失。
- 增量迁移 SQLite，保留知识 ID、版本、可追溯的远端来源和原范围锚点。现有可解析、有效且未标记缺失条目保持原有读取范围，标记「历史待复核」；无验证记录的存量不进入诊断及 AI 推荐。无法解析的条目进入治理待归类，既有历史保留。
- 上线先备份 SQLite 并核对迁移报告，再切换全部读写入口。迁移可重跑。切换后如需回退，优先恢复旧界面并保持新可见性约束；若需恢复旧数据库，从备份和审计记录核对切换后的写入，有序回放已确认数据。旧读链接继续受版本和权限规则约束。旧的直接发布请求返回冲突并提示改用草稿入口。现有批量导入及同步更新为只创建候选。

### 5. 发布验收

| 场景 | 通过条件 |
| --- | --- |
| 真故障检索 | 三类试点各准备至少 5 种经值班人员标注的查询，覆盖精确报错和中文变体。前三命中率至少 80%，关闭模型后仍能找出相同规则命中的手册。 |
| 值班任务 | 至少两位试点值班人员分别使用 Finding 推荐和直接搜索，能从详情读出第一项有效的验证动作、适用条件与预期结果。记录寻找首项步骤的用时基线。 |
| 发布与撤回 | 保存复核、建立关联、草稿和来源同步均不直接产生生效的新知识。仅审核发布后生效。撤回后列表、详情、推荐和 AI 在下一次请求均不返回该内容。 |
| 权限 | 正负授权夹具覆盖访问、筛选项、总数、关联计数、引用和 AI 上下文；同 ID 跨实例时各自独立。访客和 LDAP 默认角色维持当前可见范围。 |
| 迁移与性能 | 用脱敏旧库验证重跑不重复，旧 ID 和已授权历史版本可定位。1 万条知识固定数据集运行不少于 100 次暖态搜索，服务端 p95 ≤ 500 ms 为试点目标，记录环境及结果。 |

试点后观测搜索无结果率、故障关联手册比例、撤回传播验证和逾期复核数量。统计只采集必要字段，保留权限约束。

## LLM Wiki 知识闭环与演进

这一节保留知识闭环的分期设计与历史验收。生产检索只引用生效的已授权知识。诊断复核先保存，知识发布走候选草稿、审核和独立发布。尚未交付的自动增强、索引与同步规则按规划评审。

运维知识库下一轮迭代以 [v1.0 评审稿及其拆解](00-prd.md#文档治理与诊断联动) 为评审依据。本文件保留 Phase 3 的设计及已交付接口背景。

依据 [集成设计](design.md#llm-wiki-知识闭环与演进)。首期面向 Portal，保留 K8sGPT Result CR 的原始内容。沿用多集群 Finding、资源授权、现场证据和 Engine 模型连接。由 kube-aiops 提供内嵌 Wiki 服务、存储及接口，从空库部署。

### 用户与权限

| 角色 | 操作 |
| --- | --- |
| 诊断读者 | 查看授权范围内的原始诊断和已保存复核结论；运维知识库的引用按 Wiki 读权限访问。 |
| 复核人员 | 在授权范围内发起 AI 复核，补充观察并编辑、保存结论。首期沿用现有 AI 复核授权。 |
| 知识发布人员 | 预览并发布指定 Finding 上已保存的复核结论，发布失败时可重试。知识发布需单独授予权限。 |
| 平台管理员 | 管理持久卷备份、检索预算，查看初始化、同步及索引健康状态。 |

### 功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| WK-R01 | 接收 K8sGPT 初步诊断 | Portal 展示原始故障现象和说明。原始诊断、生成的 AI 判断与已保存的复核结论可辨认，生成期间仍可读取原始诊断。 |
| WK-R02 | 检索知识并生成增强说明 | 每次生成先按 Finding 授权范围检索一轮 Wiki，再将初步说明、最多 5 条有效引用及可用现场证据交给 AI。输出包含引用版本和待验证事项。 |
| WK-R03 | 降级与重新分析 | 区分无匹配、检索不可用和模型失败。Wiki 降级时使用现有证据，模型失败时可读取初步诊断。授权用户可重新分析，保留已确认结论。 |
| WK-R04 | 按需复核并补充信息 | 用户可一次发起结构化复核，补充观察或追问后再次复核；启用诊断版本编辑与保存。参见[诊断控制台 PRD](../diagnosis-console/00-prd.md#诊断详情内的证据复核)。 |
| WK-R05 | 独立发布知识 | 有发布权限的用户预览已保存复核结论的脱敏知识并单独确认。知识沿用稳定编号和版本；同一内容重试不会重复建档。 |
| WK-R06 | 同步并展示进度 | 页面提供待同步、已同步和待处理状态。索引确认可检索后才显示已同步。失败退避重试，达到上限可重新排队。Wiki 故障期间已确认结论仍可读取。 |
| WK-R07 | 知识复用、订正与撤回 | 每个故障生成一个稳定知识编号，包含现象、结论、证据摘要和验证建议。确认订正后发布新版本，旧任务不能覆盖新版本。撤回后从检索移除，保留审计及结论历史。 |
| WK-R08 | 多环境、多集群隔离 | 从已授权 Finding 派生授权域、环境、业务、集群实例、命名空间，Wiki 与 Portal 双重校验。作用域也用于缓存隔离。草稿、任务和引用须校验归属。 |

### 运行与安全要求

| 编号 | 要求 | 验收标准 |
| --- | --- | --- |
| WK-R09 | 脱敏和引用完整性 | 进入模型和 Wiki 的文本经过后端脱敏与长度约束。发布条目仅包含允许字段，过滤凭据、个人敏感信息和对话全文。服务端验证引用编号、版本及可见范围。 |
| WK-R10 | 限时、审计与可恢复性 | Wiki 检索默认 2 秒，生成任务同指纹并发合并。确认、同步、重试、撤回均可追溯，审计记录角色、目标、版本和结果。服务重启后通过任务租约继续处理。 |
| WK-R11 | 兼容与部署验收 | OpenAPI 与生成客户端一致。在测试集群使用内嵌 Wiki 和 K8sGPT 完成发布、检索复用、订正和撤回。 |
| WK-R12 | 自动初始化 | 首次部署由程序在现有 SQLite 持久卷创建 Wiki 表及索引并注册 API，空库可立即检索。升级与重启保留数据。Wiki 初始化失败时可识别降级。共用 SQLite 可用时保留原诊断详情。 |

### 运维知识库浏览与问答

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| WK-R13 | 导航与 Wiki 文档列表 | 「系统管理」下方有同级入口。进入后显示分页文档列表，可按需打开 AI 问答对话框。列表可组合筛选环境、业务线、类型，点击条目可查看授权文档版本。 |
| WK-R14 | 使用 Wiki 进行 AI 问答 | 对话框可关闭和重开，支持多轮追问，默认沿用列表筛选。回答以匹配的 Wiki 片段为依据，带可打开的版本引用。缺少依据、检索失败和模型失败有对应提示。 |
| WK-R15 | 问答和浏览的权限边界 | 列表、筛选项、分页总数、详情、问答和引用都按当前权限约束。切换筛选开启新会话。权限变化后重新校验会话上下文，撤回内容不再用于问答。问答不写入诊断或知识。 |

### 主动录入与远端同步

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| WK-R16 | 手工录入及文档导入 | 有权限的用户可录入正文或上传支持的文档。逐文件展示转换预览、可编辑字段和失败原因。确认后知识可在授权范围内检索。 |
| WK-R17 | 统一内容转换 | 从各入口提取 Markdown 正文和结构化元数据，保留事实和步骤。范围由后端授权，转换后校验、脱敏和限制大小。异常条目保留状态供修正。 |
| WK-R18 | 指定远端目录同步 | 管理员可配置公司自建 Wiki 的目录 URL、只读登录账号和密码、子目录范围和本地目标作用域，先测试连接与预览。可点击「立即同步」，也可启用定时同步并配置 Cron 和时区。通过校验的页面自动保存到内置 Wiki，可查看逐页结果并重试。 |
| WK-R19 | 幂等、版本和权限 | 重复上传、重复同步或重启恢复不重复建档。远端页面变更生成新版本，完整枚举后确认删除才标记缺失。校验来源及页面的目录归属，发布后可用于列表、问答及诊断增强。 |
| WK-R20 | 登录凭据与定时配置 | 新来源必须输入账号和密码。密码加密存储，支持更换，详情只显示配置状态。定时计划可启停并显示下次运行，重启后恢复。手动触发不受计划开关影响，同一来源同一身份重复触发只执行一次。 |
| WK-R21 | 按登录用户复用 Wiki 凭据 | 保存后绑定 Portal 用户及同步来源，重新登录后显示本人远端账号和密码配置状态，手动同步自动使用本人绑定。定时计划使用配置人绑定，撤销授权、停用账号或解除绑定时暂停。 |
