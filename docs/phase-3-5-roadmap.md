# Phase 3–5 路线图

当前验收基线是 [Phase 2 证据关联](phase-2-completion.md) 和 [Web Portal Demo](portal-demo.md)。后续阶段沿用 Finding 的授权范围、证据引用和审计记录，并逐步引入分析、人工批准和受控自动执行。

| 阶段 | 交付目标 | 进入条件 | 验收条件 |
| --- | --- | --- | --- |
| Phase 3 · RCA Agent + Runbook | 根据证据生成可追溯的根因假设，匹配只读排查 Runbook | Phase 2 和 Portal Demo 验收通过 | 假设可追溯到证据 ID，证据不足和来源降级可识别，Runbook 可复现，授权和只读回归通过 |
| Phase 4 · HITL Remediation | 让值班人员审阅、批准和执行预定义修复动作 | Phase 3 通过故障样例验收，动作及其回滚已在测试环境演练 | 审批绑定目标和参数，越权及重复执行被拦截，执行、复验及回滚可审计 |
| Phase 5 · Controlled Auto Remediation | 对经过人工验证的低风险动作启用策略驱动执行 | Phase 4 有稳定执行记录，灰度范围、失败停止条件和回滚路径已验证 | 影子模式评估通过，灰度有范围与频率上限，熔断和全局停止开关已演练 |

## Phase 3 · RCA Agent + Runbook

- **3.1 证据与假设。** 输入 Finding 和 `CorrelationBundle`，输出假设、支持与反向证据、缺失信号、建议排查步骤。输出包含来源状态和证据 ID，历史样例可重复验收。
- **3.2 Runbook 匹配。** 建立版本化 Runbook 库，先覆盖容器重启、Deployment 副本不足和 PVC Pending。按资源类型与证据匹配，每个步骤说明输入、预期信号和人工复验条件。
- **3.3 Portal 验收。** 在 Finding 详情中展示假设及证据引用。用脱敏样例覆盖命中、证据冲突、无匹配和来源故障。若引入模型，输出需通过结构校验并保留证据引用。

## Phase 4 · HITL Remediation

- **4.1 动作目录。** 为每项动作定义允许的资源、参数、预条件、变更预览、健康复验和回滚方法。执行身份按动作和目标范围授予权限。
- **4.2 审批与执行。** 审批绑定操作者、目标资源、计划版本、参数与有效期。执行前复核对象状态和权限，使用幂等键控制重复提交。
- **4.3 验收。** 覆盖审批过期、资源版本漂移、并发批准、执行失败、部分成功与回滚。审计记录包含审批、执行、复验和回滚结果。

## Phase 5 · Controlled Auto Remediation

- **5.1 影子模式。** 记录策略会选择的动作、目标和原因，使用 Phase 4 的人工决策和复验结果评估误触发。
- **5.2 受控灰度。** 只选已完成演练的低风险动作，从少量授权命名空间开始。限制单资源并发、命名空间频率和集群级影响范围。
- **5.3 停止与回退。** 提供全局停止开关和失败熔断。监控信号缺失、健康复验失败或超出操作预算时停止自动执行，保留审计记录供值班人员处理。

各阶段独立验收。进入下一阶段前，记录通过的测试、风险边界和操作责任人。
